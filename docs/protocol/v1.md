# This Is Fine — Adapter JSON Protocol v1

**Status:** Stable for additive changes  
**Constant:** `protocol_version: 1` (`tif_core::protocol::PROTOCOL_VERSION`)  
**Transport:** CLI stdout (and optionally stderr for human diagnostics). Prefer `--json` on all adapter calls.

## Design rules

1. **Same domain results** drive human and JSON output; adapters must use `--json`.
2. **Never invent reviewers or lower the correctness floor** via protocol fields.
3. **Exit codes:** `0` success for the operation; non-zero for hard failures (config, preflight Failed, verify required-fail, apply dual-failure, etc.).
4. **Additive evolution only** within v1. Breaking changes require `protocol_version: 2`.

## Envelope

Every JSON response is:

```json
{
  "protocol_version": 1,
  "ok": true,
  "error": null,
  "data": { }
}
```

| Field | Type | Notes |
|-------|------|--------|
| `protocol_version` | u32 | Always `1` for this document |
| `ok` | bool | Operation success |
| `error` | string \| null | Present when `ok` is false |
| `data` | object \| null | Payload when `ok` is true |

When `ok` is false, adapters **must not** proceed as if containment succeeded.

## Global CLI flags

| Flag | Meaning |
|------|---------|
| `--json` | Emit the envelope on stdout |
| `--repo PATH` | Repository root (default: discover from cwd) |

## Operations

### `tif policy resolve`

```text
tif policy resolve --task "…" [--fire-level N] --json
```

**`data`:** `PolicyResolveResult`

| Field | Type | Description |
|-------|------|-------------|
| `policy` | object | Compiled containment policy (versioned fields) |
| `compact_status` | string | e.g. `🔥 Containment active · Fire Level 3` |

### `tif run begin`

```text
tif run begin --task "…" [--agent ID] [--model ID] [--force] --json
```

**`data`:** `RunBeginResult`

| Field | Type | Description |
|-------|------|-------------|
| `run_id` | string | Stable local run id |
| `state` | string | State machine value |
| `policy` | object \| null | Policy when preflight succeeded |
| `compact_status` | string | Status line |

If preflight fails (`state` = `failed` or `error` set on the run), CLI exits non-zero and `ok` is false.

### `tif run complete`

```text
tif run complete --run-id ID \
  [--from-git | metric flags] \
  [--verification-passed true|false] \
  [--auto-firebreak] \
  --json
```

**Trusted adapter signal:** `--verification-passed` asserts checks already run by the agent. CI should **omit** this flag and use `tif verify`.

**`data`:** run summary including `run_id`, `state`, `assessment`, optional `firebreak`.

**OutOfControl runs stay open** so manual `tif firebreak --run-id` can proceed.

### `tif assess`

```text
tif assess --from-git --json
tif assess --from-diff PATH|-- --json
tif assess --files-added N --lines-added N … --json
```

**`data`:** `AssessResult` → `{ "assessment": … }`.

### `tif verify`

```text
tif verify [--dry-run] --json
```

**`data`:** `VerifyResult` → `{ "report": … }`.  
Non-zero exit when required checks do not pass / plan incomplete.

### `tif firebreak`

```text
tif firebreak --run-id ID [--auto] --json
tif firebreak --candidate PATH [--apply] [--from-git] --json
tif firebreak --invoke-backend [--task TEXT] --json
```

Phase 2 closed loop (when authorized reviewers are configured, or with `--auto`):

1. Select authorized reviewer and open isolation  
2. Invoke backend (`generate_with_backend`)  
3. Re-verify candidate with the repository verification plan  
4. Rank with absolute/git metrics (same kind both sides)  
5. Apply if smaller + within containment + floor pass and `auto_apply_firebreak` (non-sensitive); else `AwaitingApproval` when required  

Without reviewers: fail-closed (original retained).

### `tif approve` / `tif reject`

```text
tif approve <run_id> --json
tif reject <run_id> --json
```

Operate on `AwaitingApproval` runs. Approve re-verifies then applies; reject retains the original.

With `--candidate`: stage, re-verify, rank; `--apply` authorizes filesystem apply only when gates pass.

### `tif rollback`

```text
tif rollback RUN_ID --json
```

**`data`:** `RollbackResult`

| Field | Type | Description |
|-------|------|-------------|
| `run_id` | string | |
| `restored` | bool | True only if filesystem restore ran successfully |
| `reason` | string \| null | `restored`, `never_applied`, `noop`, … |
| `message` | string | Human summary |

### `tif audit show`

```text
tif audit show [--limit N] --json
tif audit --gc | --purge --json
```

### Other commands

| Command | Purpose |
|---------|---------|
| `tif init` | Create shared/local config |
| `tif on` / `tif off` | Enable/suspend containment |
| `tif status` | Compact repo status |
| `tif inspect` | Source inspection |
| `tif fire-level [1-4]` | Get/set initial Fire Level |
| `tif five-alarm --plan` | Five-Alarm plan outline (full flow in Phase 3) |
| `tif adaptation` | Local adaptation summary |
| `tif reviewer list\|probe\|test` | Authorized pool list, connectivity probe, offline backend test |
| `tif firebreak --invoke-backend` | Run authorized backend in isolation (no apply) |
| `tif tui` | Interactive TUI (requires TTY) |

## Exit code conventions

| Code | Meaning |
|------|---------|
| 0 | Success (`ok: true`) |
| 1 | General failure (config, I/O, policy, failed preflight, verify fail) |

Adapters should parse JSON when `--json` is set rather than scraping human text.

## Compatibility

- Adapters **must** check `protocol_version` and refuse unsupported majors.
- Unknown fields in `data` should be ignored (forward compatible).
- New operations may appear in minor releases without bumping protocol version if envelope unchanged.

## Security notes for adapters

1. Do not pass untrusted shell strings into verification config.  
2. Prefer argv arrays over shell interpolation for task text.  
3. Never log full source when audit tier is `metadata`.  
4. Local config (credentials) must never be committed.
